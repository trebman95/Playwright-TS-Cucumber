# Saucedemo Playwright/Cucumber Test Suite

Cucumber + Playwright coverage for the Playwright-Cucumber-Exercise take-home assignment,
against [saucedemo.com](https://www.saucedemo.com/).

Started from the assignment's unmodified scaffold, tagged
[`assignment-baseline`](https://github.com/bradevansqa/Playwright-Cucumber-Exercise/tree/assignment-baseline).
[Compare that starting point against the current state](https://github.com/bradevansqa/Playwright-Cucumber-Exercise/compare/assignment-baseline...main)
to see everything that changed.

## Run locally

```bash
npm install
npx playwright install chromium
npm test
```

The browser runs **headed** locally and **headless** in CI (`playwrightUtilities.ts` checks
`process.env.CI`), so you can watch it locally with no config changes.

| Command                           | Scope      | Notes                                                                   |
| --------------------------------- | ---------- | ----------------------------------------------------------------------- |
| `npm test`                        | everything | login, product, purchase, mocked checkout/cart, personas, HTTP contract |
| `npm run test:e2e`                | `@e2e`     | the one real, unmocked purchase walkthrough - the canary                |
| `npm run test:mocked`             | `@mocked`  | seeded-state checkout/cart/persona scenarios, no UI walk                |
| `npm run test:api`                | `@api`     | raw HTTP requests against saucedemo, no browser at all                  |
| `npm run test:agents`             | -          | runs `tests/*.spec.ts` generated by the Playwright test agents          |
| `npm run report`                  | -          | opens the HTML report from the last `npm test` run                      |
| `npm run typecheck`               | -          | `tsc --noEmit`                                                          |
| `npm run lint` / `lint:fix`       | -          | ESLint                                                                  |
| `npm run format` / `format:check` | -          | Prettier                                                                |

## Tags

| Tag                                       | Meaning                                                                               |
| ----------------------------------------- | ------------------------------------------------------------------------------------- |
| `@e2e`                                    | Full, unmocked UI walkthrough - the regression canary                                 |
| `@mocked`                                 | State is seeded directly (cookie/localStorage), skipping the UI steps that produce it |
| `@api`                                    | Raw HTTP requests via `api/httpClient.ts` - no browser, no page object                |
| `@loggedIn`                               | Fixture: real UI login as `standard_user`, cached and reused for the rest of the run  |
| `@problemUser` / `@performanceGlitchUser` | Same fixture pattern, different saucedemo test persona                                |

```bash
npx cucumber-js --tags @mocked
npx cucumber-js --tags "@mocked and not @problemUser"
```

## Structure

```text
features/    Gherkin scenarios
steps/       Step definitions
pages/       Page Object Model - locators and actions only
mocks/       Product catalog and localStorage seeding helpers
api/         Standalone HTTP client for request-level tests
hooks/       Suite lifecycle: tracing, login fixture, browser/request teardown
tests/       Playwright test agent output (not part of the Cucumber suite - see below)
specs/       Markdown test plans, read by the generator agent
```

## Playwright Test Agents

Scaffolded with `npx playwright init-agents --loop=claude`: three subagents under
`.claude/agents/` -

| Agent     | Does                                                                     |
| --------- | ------------------------------------------------------------------------ |
| Planner   | Explores a page, writes a Markdown test plan to `specs/`                 |
| Generator | Turns a plan into a runnable `tests/*.spec.ts`, verifying selectors live |
| Healer    | Runs the generated specs, diagnoses failures, patches them               |

This is a second, independent lane from the Cucumber suite above - not a replacement. The
generator and healer write and run raw `@playwright/test` files by MCP-tool design (their tools
are wired to Playwright's own runner), so their output can't be redirected into Gherkin. Use them
for fast, spec-driven exploration of new pages; the Cucumber suite stays the deliberate, curated
regression suite. `.mcp.json` wires up two MCP servers: `playwright-test` (bundled, powers these
three agents) and `playwright` (`@playwright/mcp`, general-purpose browser automation for ad-hoc
use in a Claude Code session). See [CLAUDE.md](CLAUDE.md) for the full breakdown.

## Debugging a failed run

Every scenario traces; only failures keep the trace file (`hooks/globalHooks.ts`).

```bash
npx playwright show-trace traces/<scenario-name>.zip
```

See [NOTES.md](NOTES.md) for the mocking strategy and design tradeoffs.
